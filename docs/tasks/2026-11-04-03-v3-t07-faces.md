## Background

Decision 16: face detection only, with Apple Vision; same-person grouping (Lv2) and age/gender (Lv3) are out. The spike measured Vision face rectangles at 720 px (Swift API, default revision 4, about 15 ms per request) and showed that faces on every 10th frame add no wall time to the shot scan pass. T05 left a face hook in the scan engine.

Estimate: 1 h (T06, of similar size, took 57 min of working time; the scan hook, cache and sheet machinery exist).

## Goal

The owner can scan a movie for faces (alone or with the shot scan), create a faces sheet, sort and filter it by face count, size and confidence, and see face rectangles, as `docs/V3_SPEC.md` §5 (faces), §6 (face detection) and §10 (Faces Lv1) describe.

## Scope

### In scope

1. **Detection (core + scan engine):** Vision face rectangles (Swift API, default revision) on the scan pass's 720 px frames through the T05 hook, behind a `FaceAnalyzer` protocol (so Lv2 can be added later); warm the request up when a movie opens; per face: confidence, size (box height % of frame height), relative box; per frame `{frameNumber, faceCount, largestSize, faces}` in the per-movie scan cache (resumable like the shot scan). Scope: every 10th (default) / every 100th frame between the lowest and highest visible thumb, or exactly the current thumbs; every 100th by default on the ffmpeg path. When the shot scan has not run, the face scan runs the combined pass. Confidence threshold (70) and size threshold (10 %) from §6, "takes effect on next scan".
2. **Faces sheets (§5):** Add faces sheet in the toolbar (the three scopes); frames that contain faces; grid only (timeline disabled); initial sort by face size, then optimized grid; Convert to interval.
3. **Sort and filter (§4, §10):** Sort by face count, size, confidence, plus Reverse and Frame number; Filter: face count 1–10 (default 1–3) and size (default 50–100), each toggleable; both undoable.
4. **Face rectangles overlay:** toolbar toggle; drawn on thumbs in the window, in the player view's still, and optionally in saved prints (off by default; say what you chose).
5. **Settings (§6):** Face detection section (confidence, size).

### Out of scope

- Unique faces, occurrence, FIND, same-face filter (Lv2); age and gender (Lv3); transforms, Save All and polish (T08).

### Parts

1. Detection, cache and scan integration (core, tests with a synthetic image containing a face, or Vision's behavior on a blank frame plus a fixture if no face image can be committed).
2. Faces sheets, sort, filter, overlay, settings; docs.

## Implementation Result

- Status: Completed with follow-up issues

### Changes

- Detection: `FaceAnalyzer` protocol and `VisionFaceAnalyzer` (DetectFaceRectanglesRequest, default revision) on the scan's 720 px frames through the T05 hook; thresholds applied at scan time; per frame count, largest size and faces (confidence, size %, box); warm-up on movie open.
- Scan: combined pass (shot metrics + faces) when the shot scan has not read the frames, faces-only pass otherwise, single exact frames for "These thumbs"; scopes every 10th / 100th between the lowest and highest thumb (100th by default on the ffmpeg path); analysis off the reader on two workers with a 6-frame backlog and back-pressure, committed in frame order; resumable face cache (`<id>.fsfaces`); faces-sheet thumbnails made from the scanned frames.
- Faces sheets: Add faces sheet (click for the default scope, hold for all three), frames with faces sorted by size in an optimized grid, grid only, Convert to interval; Sort (face count, size, confidence, Reverse, Frame number) and Filter (count, size; hides thumbs), one undo step each; face rectangles toggle on thumbs and the player still, optional in prints (Output, off); Face detection settings with Apply, which rescans the current faces sheet in place.
- Clear Stored Scans in the movie menu; scan files of removed movies are deleted at launch.
- Scan timing log `~/Library/Logs/FrameSheet/scan.log`; `scripts/check.sh` keeps its output in `~/Library/Logs/FrameSheet/check.log`.

### Bugs found and fixed

- Every face-scan progress event redrew the toolbar, every movie row and the settings panel (the main cause of a 3 min scan in the app).
- The faces sheet's ~400 thumbs were decoded one by one (open-GOP film: minutes) and at 640 px overflowed the 256 MB cache; now they come from the scan and window thumbs are decoded at their drawn size.
- Thumb requests made the scan pause about every second; now at most every 3 s, serving all waiting requests at once.
- Changing a thumb's frame kept the old frame's face rectangles.
