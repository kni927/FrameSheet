# TASK: v3 skeleton (Swift package, core models, first interval sheet)

From: FrameSheet HQ (via handoff-relay), 2026-11-02.

## Background

v3 rebuilds FrameSheet as a reproduction of MoviePrint v0.2.23 (`docs/V3_SPEC.md`; decisions 14–22 in `docs/DECISIONS.md`). The measurement spike fixed the scan design (`docs/v3-measurements.md`). Before features, the repository needs the v3 package layout, the core model, the decode layer and a minimal app that proves the path from a movie file to a grid of thumbs. Decision 20: v3 lands on `main` and the v2 sources go when the skeleton lands.

## Goal

A v3 app that builds with `./build.sh`, launches, takes movies by Add movies or drop, lists them, and shows a default interval sheet (16 thumbs, 4 columns) for the selected movie — on a tested core library — with the v2 sources removed.

## Scope

### In scope

1. **Swift package at the repository root** (`Package.swift`, Swift 6 language mode, macOS 27, arm64): library `FrameSheetCore` (no SwiftUI/AppKit), executable target `FrameSheet` (the app), test target `FrameSheetCoreTests` (`swift test`). `tools/spike` stays its own package, untouched.
2. **Core model** (`docs/V3_SPEC.md` §3): library of movie files, sheets (interval/shot/faces, grid/timeline, columnCount, secondsPerRow, parentSheetId), thumbs, scenes, settings; all Codable. Sheet naming `MoviePrint-N` per file. Interval frame list: N frames evenly between IN and OUT (§5). Grid geometry (§5.1) as a pure function. Library persistence as JSON in Application Support (§12), with a round-trip test. Undo is not in this TASK.
3. **Decode layer**, ported from v2 after review (`src/DecodeBackend.swift`, `AVFoundationBackend.swift`, `FFmpegBackend.swift`, NFC path helpers from `Extensions.swift`), adapted to Swift 6 concurrency and the v3 conventions in `CLAUDE.md` (Decode Conventions): probe (duration, frame count, fps, size, fourCC), thumbnail extraction with `AVAssetImageGenerator` (zero tolerance, one ±0.5 s retry keeping the decoded time), routing to ffmpeg when AVFoundation has no decodable track or the HEVC sample entry is `hev1` (§10). ffmpeg discovery in the spec's order (§10), validated with `ffmpeg -version`. Sequential scanning (`AVAssetReader`) is not in this TASK.
4. **Minimal app**: one window, dark appearance, with the §4 layout as a frame — movie list sidebar (poster, name, folder, duration, size, W×H; sheets under each movie), main area with the grid of the selected sheet, settings sidebar as an empty placeholder with the ffmpeg path/version row. Add movies (open panel, key A) and drop; selecting a movie creates its default interval sheet (16 thumbs, 4 columns) on first selection. Thumbnails in an `NSCache` with a cost limit (default 256 MB, §6). Colours from the Catppuccin Mocha palette in one theme file (the kni Design System's base; its type and spacing tokens come in a later TASK).
5. **Build**: `build.sh` builds with `swift build -c release --scratch-path` outside the repository, assembles `build/FrameSheet.app` from the `FrameSheet` product (Info.plist with `LSMinimumSystemVersion` 27.0, arm64 only, icon from `src/assets/AppIcon.png` moved to a v3 location), and keeps the signing, tag-derived version and zip steps.
6. **Remove v2**: delete the remaining v2 `src/` files and `tests/baselines` (decision 12 no longer applies; say so in a short note under decision 12). v2 stays at tag v2.3.1.
7. **Docs**: rewrite `docs/PROJECT.md` and `docs/ARCHITECTURE.md` for v3; update `README.md` (v3 in development, requirements, build); `docs/STATUS.md`; `docs/KNOWN_ISSUES.md` (drop or mark obsolete what only applied to v2). Update `CLAUDE.md` Commands (Build, Test) — this needs the owner's approval in your chat naming `CLAUDE.md`; ask once, and if it is refused, put the exact text in your report.

### Out of scope

- Shot scan, faces, timeline view, player view, hover overlay, scrub, export/import, undo, the full settings panel.
- Version number change or tag (a task of its own).
- The kni Design System's type and spacing tokens.

- Deviation: the TASK named "NFC path helpers from `Extensions.swift`"; v2 had none there (NFC was inline in `FFmpegBackend`), so v3 has `URL.nfcPath` in `ProcessRunner.swift`.

Bugs found and fixed (f0d9c18): the last interval thumb failed on both paths. AVFoundation took the duration from the asset (a longer audio track put the last frame past the video); it now uses the video track's time range and reports the frame actually decoded. On the ffmpeg path the frame count from duration × fps exceeded the real count; a missing frame now retries 0.5 s earlier and names the frame it got.
