## Scope

### In scope

1. **Version before the tag:** let `build.sh` take an explicit version (for example `FRAMESHEET_VERSION=3.0.0`) that wins over `git describe`, so the verified build carries 3.0.0 before the tag exists; keep the tag-derived default. Record the build's commit; the tag must point at exactly that commit.
2. **Notarization:** find the notarytool credentials already set up on this Mac (`xcrun notarytool history --keychain-profile <name>`; ask the owner for the profile name if you cannot find it). Never print, copy or store a secret; creating a new keychain profile or app-specific password is the owner's step (ask, with the exact command). Add a release step to `build.sh` or a script `scripts/release.sh` that signs (hardened runtime), zips, submits with `notarytool submit --wait`, staples, re-zips the stapled app, and checks with `spctl --assess --type execute -vv` and `stapler validate`. If it is a new script, list it in `.claude/settings.json` `permissions.ask` (a release step must always ask) and under `CLAUDE.md` Commands; both need the owner's approval in your chat naming the files.
3. **Release notes:** `docs/release-notes/v3.0.0.md` (en-US): what v3 is (MoviePrint 0.2.23 reproduced for Apple Silicon, macOS 27), the main features by area, requirements (macOS 27, Apple Silicon, ffmpeg optional for WebM/MKV/hev1 and exact-frame fetching), what is not included (face grouping, age/gender, guide layout), known issues (KNOWN_ISSUES 1, 2, 4, 5, 6), and the MoviePrint MIT credit.
4. **Docs:** README (v3.0.0, download from the Release, requirements, first launch), DEV_LOG (one milestone line), STATUS, KNOWN_ISSUES 3 (resolve once the tag exists).
5. **Hand over the tag, then publish:** stop and give the owner one ready-to-paste block: `git tag -a v3.0.0 -m "v3.0.0" <commit>` then `git push origin v3.0.0`. After the owner pushes it, confirm the tag points at the built commit, then create the GitHub Release with the notarized zip and the notes (`gh release create v3.0.0 <zip> --title "FrameSheet v3.0.0" --notes-file docs/release-notes/v3.0.0.md`; check `gh auth status` first). Creating the Release is an outside effect: name it in your chat and get the owner's go there, even though the owner approved the plan in the HQ's chat.
